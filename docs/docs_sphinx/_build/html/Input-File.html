Input File

A TDSE-Z run is configured by one plain-text input file, passed with -inp <file> (default tdse.prm; see CLI Flags). This page describes the syntax and lists every key that the parser accepts, with its type, default and meaning. The physics behind each group is explained on the linked pages.

Syntax

  • Each setting is one line Key = value. Leading and trailing white space of key and value is removed.

  • # starts a comment that extends to the end of the line. A # therefore cannot occur inside a value.

  • Lines without = are ignored.

  • Key names are case-sensitive. Values are taken literally: quotation marks are not removed and become part of the value, so values are written without quotes.

  • Each key may appear only once. A repeated key is a fatal error with StrictInput = 1 and a warning (the last value is used) with StrictInput = 0. Variables is the only key that may be repeated; its lines accumulate.

  • An unknown key is a fatal error with StrictInput = 1 (default) and a warning with StrictInput = 0. StrictInput takes effect from the line on which it appears, so StrictInput = 0 must precede the keys it should tolerate.

  • Aliases are alternative names for the same setting. A key and its alias count as different keys for the repetition check; give only one of them.

Value types

Type

Accepted values

int, real

A decimal number (1e-3 notation allowed). Integers are read with std::stoi, reals with std::stod.

bool

true/yes/on or false/no/off (case-insensitive), or an integer (non-zero is true).

string

Free text, used as given. Enumerated values are listed per key; where noted they are case-insensitive.

expression

A muParser expression (see Expressions).

list[3]

Per-axis values vx, vy, vz. A single value applies to all three axes. With two values the third axis keeps its default (the field lists DriverAmplitude, DriverFrequency, DriverCEP and their aliases instead fill missing entries with the first value).

Expressions

Potential, PotentialDerivativeX/Y/Z, Mass and the field keys Laser, LaserX/Y/Z are evaluated with muParser. The spatial expressions use the variables x, y, z (atomic units), the field expressions the time t. Available in every expression:

  • the muParser built-in functions and operators (for example sin, cos, exp, sqrt, abs, min, max, ^ and the ternary operator cond ? a : b);

  • the constant pi;

  • the input scalars Q and Charge, Dimension, SplineDegree, Nelements and NSplines, LMinX … LMaxZ, OffsetX/Y/Z, Ampx/y/z, CEPx/y/z, Omegax/y/z, TargetEigenvalue, TimeStep, FinalTime, CAPKmin, KnotAlpha, NQuadratures and NBoundStates, with the values given in the input file;

  • user constants declared with Variables.

In the spatial expressions fabs( is replaced by abs( before parsing.

Variables = Name=value, Name=value, ... declares named numeric constants. Several Variables lines accumulate:

Variables = V0=1.2, w=0.5
Variables = Rc=4.0          # adds Rc; V0 and w remain defined
Potential = -V0*exp(-w*(x^2+y^2)/Rc^2)

After parsing, the input is validated (ValidateOrThrow) before any matrix is assembled; an inconsistent combination stops the run with a message that names the offending key. The checks are listed with the keys below.

Example

A minimal 1D high-harmonic run (soft-core atom, \(\sin^2\) pulse, absorbing boundaries); a complete deck is examples/hhg/hhg_1d.inp:

# 1D model atom, HHG with absorbing boundaries
Dimension     = 1
Domain        = -200, 200
Nelements     = 800
SplineDegree  = 5
KnotSequence  = uniform

Variables     = a=2.0, T=1763.7
Potential     = -1/sqrt(x^2 + a)
PotentialDerivativeX = x/(x^2 + a)^1.5
Mass          = 1.0

NBoundStates     = 1
TargetEigenvalue = -0.5

Polarization  = x
Ampx          = 0.0534
Omegax        = 0.057
LaserX        = Ampx*sin(pi*t/T)^2*sin(Omegax*t)

TimeStep      = 0.05
FinalTime     = 1763.7
Propagator    = pade22
EnableCAP     = 1
CAPWidth      = 50
